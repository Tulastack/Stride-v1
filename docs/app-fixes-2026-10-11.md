# Analysis, reconstruction and app coach fixes

The coach can now prepare exact calendar additions, date moves, edits and deletions, profile edits, navigation to all six tabs and appearance changes. It reads the user's analysis history, trusted metric trends, drill library, suggestions, calendar, profile/recovery flags and coach-session metadata through explicit tools. Coaching now has enough rounds to read IDs, reason over returned data, then prepare actions; relevant findings are no longer silently truncated at 1,200 characters.

Coach access is off by default. The athlete enables analysis, calendar, profile and/or app access in the chat's **Coach access** panel. Choices are stored per account. Read permissions are enforced before data fetching, including the fallback completion. Model-written prose cannot report that an unapproved action succeeded: action replies are derived from the actual signed proposals. The athlete reviews dates, titles and workout details and taps **Review and apply**. Dismissed actions do nothing. User/session-bound HMAC tokens expire after 30 minutes. Calendar and profile writes are transactional, ownership-scoped, protected against stale edits, and retry-safe through receipts. Completed training cannot be moved/deleted by the coach. Calendar training changes respect the app's injury pause. Switching accounts invalidates in-flight chat responses. Revoking a category clears conversation history so previously shared measurements are not sent back under revoked permissions.

## Reconstruction and analysis

The worker now publishes actual reconstructed COCO-17 joints with original-video timestamps; the viewer supports scrubbing, orbit and playback, respects reduced motion and hides missing/uncertain joints. RTMW3D also writes original-image 2D overlays. No ideal gait is substituted for reconstruction.

`STRIDE_PIPELINE=auto` now selects locally provisioned RTMW3D weights when available; otherwise it attempts the model-free geometric path. No learned weights are downloaded or bundled by this change. An explicit `2d`, `3d`, `3d-geo`, `wham` or `legacy` setting still wins. Local launch scripts, Docker and Terraform now agree on `auto`. When an explicit learned path lacks its weights, it falls back to geometric reconstruction. Poor scale, poor closure, unusable metrics or reconstructed motion inconsistent with the original running footage cause a 2D fallback. The rejected skeleton is not displayed as a successful reconstruction. Geometric fallback provenance now records the actual 2D backend.

A real regression was reproduced on IMG_0271.MOV: the geometric path called the subject static, emitted no flaws/focus areas and scored it 71. The source video showed running motion. The new guard switches that case to source-2D analysis: one confirmed flaw, four tentative focus areas, score 83. This demonstrates recovery of the app's analysis behavior, not that 83 is a ground-truth grade.

Original frame indices now survive both whole-clip and multi-segment analysis. Frontal evidence is dated to the actual frontal segment. Each metric family uses its own segment observability when gating trust, and a trust demotion can no longer leave a confirmed flaw behind. Cadence's TypeScript frame-rate gate now matches the worker's 30-fps gate; contact time remains stricter.

Usability and trust are separate. Usable experimental readings remain visible as approximate estimates with uncertainty and explicit unconfirmed labels. Unusable readings stay withheld. Unknown historical trust defaults to experimental. Only explicitly trusted readings at confidence >=0.6 can produce confirmed faults or feed progress trends; stored historical reports and historically polluted timeline rows are checked on reads too. Trends compare the latest matching phase and pipeline. A placeholder zero with no usable readings is not displayed as a grade. Both coach paths retain tentative focus areas and exclude unusable facts and unsupported faults.

## Validation and evidence

See [the recorded checks](verification/2026-10-11-app-fixes.json). Three real clips completed with the locally installed learned model and 75–180 reconstructed frames. Two distant clips correctly took the geometric path's 2D fallback; a close clip reproduced and then passed the motion-consistency fallback. These runs patched only publishing callbacks to capture artifacts rather than write athlete analyses. The live configured coach provider prepared the exact requested move and deletion from synthetic records without writing calendar data.

API tests exercise the shipping coach router, consent-denied reads, revoked access, forged approvals, wrong-owner approvals and server-owned pending wording. Real local PostgreSQL tests cover create/retry/move/delete, stale edit rejection, completed-training protection and both new/historical progress trust filtering. Mobile tests cover review cards, explicit apply, conversation retries and measurement disclosure. Worker tests cover reconstruction serialization, missing joints, timestamp preservation and pipeline selection. TypeScript checks and iOS Hermes export also pass. Final suites: 213 API tests, 165 mobile tests, 111 worker tests; three additional real-PostgreSQL tests passed separately.

These checks do not establish motion-capture accuracy, visual quality on an installed phone, or production acceptance. Real-video scores have no ground-truth reference. The iOS simulator is unavailable (`xcrun simctl` is not installed). No production code or schema was deployed.

## Rollout

The local test database has the receipt migration applied. Before deploying the API, apply `db/migrations/2026-10-11-coach-actions.sql` to PostgreSQL, or use the existing DSQL migration command against the updated canonical `db/schema.sql`. The DSQL schema omits foreign keys; account deletion explicitly removes receipts there. `COACH_ACTION_SECRET` can supply a dedicated signing key; otherwise the existing required `INTERNAL_API_SECRET` signs approvals. All API instances must share that key. Deploy/restart both API and worker and install the new mobile bundle. Old reports gain safer trust filtering, but need reanalysis to gain a reconstructed-pose payload. Complete phone/LAN, native scrub/orbit, account-switch, consent-toggle, calendar refresh and production callback checks before calling the release accepted.
